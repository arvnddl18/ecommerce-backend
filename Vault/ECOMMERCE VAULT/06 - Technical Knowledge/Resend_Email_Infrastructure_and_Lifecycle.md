## 1. Overview
The platform uses **[Resend](https://resend.com/)** for transactional email delivery. Laravel integrates natively with Resend via the `resend/resend-php` SDK and `Illuminate\Mail\Transport\ResendTransport`.

```
[Stripe Webhook / API Event]
          │
          ▼
 [ProcessStripeWebhookJob]
          │
          ├──> Mail::to($buyer)->queue(new OrderConfirmationMail($order))
          └──> Mail::to($seller)->queue(new SellerOrderNotificationMail($order, ...))
                     │
                     ▼
          [Queue Worker / Redis / Sync]
                     │
                     ▼
          [Resend API (HTTPS /v1/emails)]
                     │
                     ▼
             [Customer / Seller Inbox]
```

## 2. Configuration & Credentials

### Environment Variables
- `MAIL_MAILER=resend`
- `RESEND_API_KEY`: Injected into `.env` (Never committed to VCS).
- `MAIL_FROM_ADDRESS`: Default `onboarding@resend.dev` in sandbox testing; updated to verified domain (e.g. `orders@fold-apparel.com`) for production.
- `MAIL_FROM_NAME`: `${APP_NAME}` ("FOLD").

### Framework Service Binding
- `config/services.php`:
  ```php
  'resend' => [
      'key' => env('RESEND_API_KEY'),
  ],
  ```
- `config/mail.php`:
  ```php
  'mailers' => [
      'resend' => [
          'transport' => 'resend',
      ],
  ],
  ```

## 3. System Email Lifecycle & Touchpoints Map

### Active Touchpoints in Source Code
1. **Buyer Order Confirmation (`OrderConfirmationMail`):**
   - **Trigger:** Centralized in `ProcessStripeWebhookJob::fulfillOrder()`. Triggered on both `checkout.session.completed` and `payment_intent.succeeded` events, as well as direct checkout session verification in `CheckoutController::getOrderStatus()`.
   - **Automatic Execution:** Every successful order purchase resolves `$buyerEmail = $order->customer_email ?: $order->user?->email;` and automatically queues `OrderConfirmationMail($order)`.
   - **Subject:** `"Your FOLD Order #{$order->order_number} has Passed Through & is Confirmed"`
   - **Template:** `resources/views/emails/order-confirmation.blade.php`.
   - **Data:** Verified pass-through badge, itemized cuts and variants (Size, Color, SKU), item prices, coupon discounts, total amount in PHP (`₱`), delivery address, and direct link to live order docket.
2. **Seller Dispatch Notification (`SellerOrderNotificationMail`):**
   - **Trigger:** Handled in `ProcessStripeWebhookJob::fulfillOrder() -> processSellerFulfillmentAndTransfers()`.
   - **Template:** `resources/views/emails/seller-order-notification.blade.php`.
   - **Data:** Order number, studio garments to cut/pack/dispatch, net payout after 10% platform fee.

### Planned Lifecycle Extension Points
1. **Shipping & Dispatch Tracking:**
   - **Trigger:** `SellerController::updateFulfillment` when status becomes `shipped`.
   - **Recipient:** Buyer.
   - **Purpose:** Provide tracking number and estimated arrival.
2. **Refund Receipt:**
   - **Trigger:** `AdminController::refundOrder`.
   - **Recipient:** Buyer.
   - **Purpose:** Confirm return of funds via Stripe and inventory restocking.
3. **Seller Studio Application Moderation:**
   - **Trigger:** `AdminController::updateSellerStatus` (`approved` or `rejected`).
   - **Recipient:** Seller user.
   - **Purpose:** Notify applicant of studio review outcome.
4. **Buyer & Seller Welcome Onboarding:**
   - **Trigger:** `AuthController::register`.
   - **Recipient:** New user.
   - **Purpose:** Confirm account creation and invite to explore the catalog or set up studio.
5. **Low-Stock Inventory Warning:**
   - **Trigger:** Inventory decrement event in webhook or order processing when stock drops $\le 2$.
   - **Recipient:** Seller merchant.
   - **Purpose:** Alert seller to restock before garment listing is marked unavailable.

## 4. Sandbox vs. Production Deliverability Rules

1. **Sandbox Testing (`resend.dev`):**
   - Without domain verification, emails sent through `onboarding@resend.dev` will succeed if sent to the registered Resend account owner email.
   - Sending to unverified external emails under the sandbox address will be rejected with `403 Forbidden` from Resend API.
2. **Production Custom Domain Verification:**
   - Requires adding the sending domain in the Resend console.
   - DNS records to configure:
     - **SPF**: `TXT` record with `v=spf1 include:amazonses.com ~all` (or Resend designated include).
     - **DKIM**: 3 CNAME records generated by Resend.
     - **DMARC**: `TXT` record `_dmarc.yourdomain.com` with `v=DMARC1; p=none;`.

## 5. Security & Push Protection
- `.gitignore` specifies `.env` and `.env.*` wildcards (with explicit exclusions for `.env.example`, `.env.production.example`, and `.env.docker`).
- `.dockerignore` blocks `.env*` to prevent multi-stage image leaks.
- Tracked template files contain only dummy tokens (`RESEND_API_KEY=re_your_api_key_here`).
